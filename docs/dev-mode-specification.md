# BatriTable 開発者モード（Developer Mode）仕様書

> **バージョン**: v1.0.0 (基盤構築 & スキーマ/プロパティシステム)  
> **作成日**: 2026-10-12  
> **運営**: SOLVENTER  
> **ステータス**: 初回実装完了  

---

## 1. 概要とコンセプト

### 1.1 背景と目的
従来のBatriTableは、Webブラウザ上で物理的な卓を囲むように「自由にマウスでカードやコマを動かして遊ぶ」アナログシミュレーター型の環境でした。  
**開発者モード（Developer Mode）**は、これをさらにデジタルTCG/ボードゲーム制作ツールへと昇華させ、
- カードに「属性・数値（構造体タグ）」を持たせる
- エリアに明確な役割とプレイヤー所有権を持たせる
- ボタンによる自動化アクション（移動、回転、表裏反転など）を定義する
- **ホストがCPUの思考・行動ルールを設定し、ソロプレイやテスト対戦を可能にする**

ことを目的とした統合開発＆実行環境です。

### 1.2 既存モードとの差別化
| 項目 | 通常ゲームモード (`game.html`) | 開発者モード (`game-dev.html`) |
|---|---|---|
| **対象ユーザー** | 一般プレイヤー（対人プレイ中心） | ゲーム制作者・ルール設計者・ソロテスター |
| **ファイル構成** | `game.html` / `game.module.js` | `game-dev.html` / `game-dev.module.js` / `game-dev.css` |
| **フィールド初期状態** | プリセットレイアウト（スタンダード1等） | 中央にメインプレイエリア1つのみ + 全面方眼ルーラー |
| **操作体系** | ダブルクリック回転・右クリック反転など直感的操作 | 右クリック「プロパティ」による属性定義・開発者向け精密操作 |
| **カードの性質** | 画像オブジェクト（見た目と位置） | **構造体データ（カードタイプ + タグ値）** を保持するエンティティ |
| **操作パネル** | 固定機能（ダイス、カウンター、シャッフル等） | **「開発者モード設定」** および **制作者が定義する「プレイ用ボタン」** |
| **CPU対戦** | なし | 将来的にビジュアルロジックによるCPUソロ対戦をサポート |

## 2. システム構成と導線

### 2.1 入室フロー
1. **ロビー画面 (`lobby.html`)**:
   - 先行開発期間中は、特定開発者アカウント（`joe9bk@gmail.com`）でログインしている場合のみ、「ゲームの種類」欄に **「🛠️ 開発者モード」** ボタンが表示される。
   - 未ログイン（ゲスト）および他アカウント時は非表示とし、URL直接入力時もロビーへリダイレクトガードを実行。
   - ※ 完成後に全ログイン（非匿名）ユーザーへ開放予定。
2. **ルーム作成**:
   - 任意の「ルームID」を入力し、「ゲームの種類」で「開発者モード」を選択して「作成」ボタンをクリック。
   - レイアウト選択モーダルはスキップされ、自動的に `game-dev.html?id=[ROOM_ID]` へ遷移。
   - Firestoreのルームドキュメント (`rooms/{roomId}`) には `fieldMode: 'dev'`, `fieldLayout: 'dev'` が記録される。

## 3. 画面レイアウトとUI

### 3.1 上部バー（Top Bar）
既存の操作性を踏襲し、アセット配置の利便性を保つ：
- **🃏 カードを追加**: 複数画像アップロードによるカード一括生成（デフォルトサイズ 120×160px）
- **🗺️ ボードを追加**: 背景/盤面用画像の配置
- **♟ コマを追加**: トークン/コマの配置
- **部屋情報 / 退室ボタン**: ルームID表示、コピー、ロビーへの安全な退出

### 3.2 メインフィールド（Canvas / Workspace）
- **全面ルーラー（マス目グリッド）**:
  - フィールド全体にグリッド線（50pxメッシュ）が常時表示され、座標把握とレイアウト調整が容易。
- **初期配置エリア**:
  - 初回入場時は、フィールド中央に「共有プレイエリア」が1つのみ配置されたクリーンな状態。
- **エリアのドラッグ＆リサイズ**:
  - エリア枠の右下リサイズハンドルをドラッグすることでサイズを直感的に変更可能。

### 3.3 左側操作パネル（Sidebar）
開発者モード専用に刷新されたサイドバー。2つの大カテゴリで構成される：

#### カテゴリ 1: 「開発者モード」設定
カードゲームの基礎スキーマやフィールド構成を構築するカテゴリ：
- **カード全般設定ボタン (`#dev-card-schema-btn`)**:
  - カードのデータ構造体（カードタイプ）を定義するモーダル。
  - **カードタイプ追加**: 例「トランプ」「モンスター」「スペル」など
  - **タグ追加**: 各カードタイプ配下に任意のプロパティ（キー）を定義（例: `Mark`, `Number`, `Cost`, `ATK`, `HP`）
- **エリア追加ボタン (`#dev-add-area-btn`)**:
  - モーダルが開き、以下の条件を指定して新規エリアをフィールドに追加可能：
    - **エリア種別**: 手札エリア (`hand`) / デッキエリア (`deck`) / デッキエリア2 (`deck2`) / 捨て札エリア (`discard`) / 特殊エリア (`special`)
    - **所属プレイヤー**: 共有 (`shared`) または プレイヤー1〜10 (`player1`〜`player10`)
  - 追加されたエリアは、識別用ヘッダー（例: `P1 手札`, `共有 デッキ`）とリサイズハンドルを備える。

#### カテゴリ 2: 「プレイ用」設定
プレイヤーが実際にゲームを操作するためのUIを設計・テストするカテゴリ：
- **操作プレイヤー選択 (`#dev-acting-player`)**:
  - 「自分の〇〇エリア」を解決する際に、誰がボタンを押したことにするかを指定（P1〜P10）。ブラウザごとに `localStorage`（`pa:dev-acting-player`）へ記憶。
  - 将来のマルチプレイ対応時は、着席中の座席番号がこの役割を担う。
- **ボタン追加ボタン (`#dev-add-button-btn`)**:
  - プレイ時の操作パネルに表示するカスタム実行ボタンを定義するモーダル。
  - **動作を最初に選び、その内容によって以降の入力欄が切り替わる**動的フォーム。

  | 入力欄 | 移動 | 裏表を変える / 裏にする / 表にする | 回転する | 向きをそろえる |
  | --- | :---: | :---: | :---: | :---: |
  | ボタン名 | ○ | ○ | ○ | ○ |
  | 対象（なにを） | ○ | ○ | ○ | ○ |
  | 移動先（どこに） | ○ | ― | ― | ― |
  | 置き方 | ○ | ― | ― | ― |
  | 角度（0〜360°、プリセット 0/90/180/270） | ― | ― | ○（回転量） | ○（そろえる向き） |
  | 方向（右回り / 左回り） | ― | ― | ○ | ― |

  - **対象（なにを）の選択肢**:
    - 「選択中のカード」
    - 「自分の〇〇エリアの全カード」… プレイヤー所属のエリアが存在する種類のみ表示。押した人（操作プレイヤー）に合わせて対象エリアが変わる。
    - 「〇〇エリアの全カード」… フィールド上に存在するエリアのみ、エリア名（例: `P1 手札エリア`、`共有 プレイエリア`）で表示。
  - **移動先（どこに）の選択肢**: 対象と同じ構成（「選択中」を除く）。**移動元と同じエリアは選択肢から除外**。
  - **置き方**:
    - 自動（既定）: 手札エリアは「並べる」、それ以外は「重ねる」
    - 重ねる: エリア中央に積み重ねる（移動したカードが最前面）
    - 横に並べる: 移動先に既にあるカードも含めて横一列に並べ直す。入りきらない場合は重ねて詰める。
  - **回転する**: 今の向きから指定角度だけ回す（相対）。0°/360° は変化しないため登録不可。
  - **向きをそろえる**: 指定した向きに揃える（絶対。0°＝縦向き）。TCG の「アンタップ」に相当。
  - フィールドにエリアがない場合は、モーダル内に案内文を表示。
- **プレイ用ボタン表示領域 (`#play-buttons-container`)**:
  - 設定されたカスタムボタンが即座にここに配置され、クリックして動作をテストできる。
  - 各ボタンには設定内容の要約（例: `移動：自分の手札エリア → 共有 捨て札エリア`）を小さく表示。
  - **参照先エリアが削除されたボタン**は ⚠ 付きのグレー表示となり、押しても実行されず理由をトースト表示。
  - 実行時の通知（トースト）:
    - 「選択中」で未選択 → 「カードを選択してください」
    - 対象エリアにカードがない → 「〇〇にカードがありません」
    - 操作プレイヤーの「自分の〇〇エリア」がない → 「P2 の手札エリアがありません」

## 4. データモデル仕様

### 4.1 カードタイプとタグ定義 (Card Type Schema)
開発環境内の `cardSchemas` として管理され、ルーム設定に保存される。
```json
{
  "cardSchemas": {
    "type_trump": {
      "id": "type_trump",
      "name": "トランプ",
      "tags": [
        { "id": "tag_mark", "name": "Mark", "type": "string" },
        { "id": "tag_number", "name": "Number", "type": "number" }
      ]
    },
    "type_unit": {
      "id": "type_unit",
      "name": "ユニット",
      "tags": [
        { "id": "tag_cost", "name": "Cost", "type": "number" },
        { "id": "tag_atk", "name": "ATK", "type": "number" },
        { "id": "tag_hp", "name": "HP", "type": "number" }
      ]
    }
  }
}
```

### 4.2 カードインスタンスのプロパティ (Card Entity Data)
各カードオブジェクトが個別に保持する拡張データ：
```json
{
  "id": "card_abc123",
  "x": 350,
  "y": 200,
  "z": 10,
  "angle": 0,
  "isFaceDown": false,
  "frontUrl": "...",
  "backUrl": "...",
  "cardTypeId": "type_trump",
  "tagValues": {
    "tag_mark": "Spade",
    "tag_number": 13
  }
}
```

### 4.3 エリアデータ (Area Data)
```json
{
  "id": "area_xyz789",
  "type": "hand",
  "owner": "player1",
  "name": "P1 手札エリア",
  "x": 100,
  "y": 600,
  "w": 400,
  "h": 180
}
```

### 4.4 プレイ用アクションボタン (Play Action Buttons)
`playButtons` 配列としてルームに保存。対象・移動先は「参照」オブジェクトで表現する。

| 参照 `kind` | 意味 | 追加フィールド |
| --- | --- | --- |
| `selected` | 選択中のカード（対象のみ） | ― |
| `own` | 操作プレイヤーの〇〇エリア | `areaType` |
| `area` | 特定のエリア | `areaId` |

```json
[
  {
    "id": "btn_1",
    "label": "手札を捨て札へ",
    "action": "move",
    "target": { "kind": "own", "areaType": "hand" },
    "dest": { "kind": "area", "areaId": "area_xyz789" },
    "placement": "auto"
  },
  {
    "id": "btn_2",
    "label": "タップ",
    "action": "rotate",
    "target": { "kind": "selected" },
    "angle": 90,
    "direction": "cw"
  },
  {
    "id": "btn_3",
    "label": "全部アンタップ",
    "action": "set_angle",
    "target": { "kind": "area", "areaId": "area_play_center" },
    "angle": 0
  }
]
```
- `action`: `move` / `flip_toggle` / `flip_down` / `flip_up` / `rotate` / `set_angle`
- `placement`（move のみ）: `auto` / `stack` / `spread`
- `direction`（rotate のみ）: `cw`（右回り）/ `ccw`（左回り）
- 旧形式（`target: "all_hand"`, `action: "rotate_90"` 等）のボタンは読み込み時に自動で新形式へ変換される。
- 将来拡張: 1つのボタンで複数の動作を順に実行する（`steps` 配列化）。

## 5. オブジェクト操作（プロパティインスペクター）

カード・ボード・コマに対する操作体系：
1. **右クリック**:
   - 開発者モード専用のコンテキストメニューが表示され、最上部に「⚙️ プロパティ」が表示される。
2. **プロパティ設定ウィンドウ**:
   - カードの場合:
     - 登録済みカードタイプを選択するドロップダウン（例: なし、トランプ、ユニット）
     - 選択されたカードタイプに紐づくタグ一覧が動的入力フォームとして表示（例: Mark入力欄、Number入力欄）
     - 「保存」を押すと、カードのメタデータとして即座に格納・反映される。
   - ボード・コマの場合:
     - 名前、幅・高さ、固定状態などの基本プロパティ設定が可能。

## 6. 今後の拡張ロードマップ (Roadmap)

1. **Phase 1 (完了)**:
   - ロビー導線・`game-dev.html` 独立基盤・グリッド＆エリア追加・カードスキーマ設定・プロパティエディタ・カスタムボタン基本動作。
2. **Phase 2 (拡張アクション & エリア連動)**:
   - 「山札から1枚引いて手札へ」「特定のタグ条件（例: Cost <= 3）を満たすカードを検索・移動」などの高度アクション定義。
3. **Phase 3 (CPUロジック・ビジュアルプログラミング)**:
   - CPUターンの概念導入。
   - 「CPUの手札から最もNumberが大きいカードをプレイエリアに出す」などのルールをノード/ブロックUIで構築し、ソロ対戦を実行する機能。
