## 1. アプリ概要

BatriTable は、**画像をアップロードしてカード化し、最大4人でオンライン対戦できるボード／カードゲームプラットフォーム**。ブラウザだけで動作し、インストール不要・基本無料。

### コンセプト
- ユーザーが**自分だけのカードゲーム・ボードゲーム**を自由に作り、即座に友達と遊べる
- カードの**ドラッグ・回転・表裏反転・シャッフル**など、リアルに近い操作体験を提供
- ダイス・トークン・カウンターなど補助機能も搭載し、多様なゲームルールに対応

## 4. 認証システム

### 認証フロー

```
初回アクセス → 既存セッション確認
  ├─ なし → 匿名ログイン → ゲーム利用可能
  └─ あり → セッション復元 → ゲーム利用可能
                                 ↓
                          Googleログイン（任意）
                                 ↓
                          匿名→Google紐付け
                                 ↓
                          マイページ利用可能
```

| 項目 | 仕様 |
|---|---|
| **匿名ログイン** | 初回アクセス時に自動で `signInAnonymously`。ルーム作成は24時間に1回まで制限 |
| **ログインユーザー** | Googleまたはメール/パスワード認証。ルーム作成可能（同時保持上限: 無料10部屋 / プレミアム100部屋）、ルーム保存可能 |
| **Googleログイン** | ロビー画面のボタンからポップアップ認証。匿名アカウントに `linkWithPopup` で紐付け |
| **永続化** | `browserLocalPersistence`（タブ跨ぎでセッション維持） |
| **ログアウト** | 認証解除 → 匿名状態に戻る |
| **ID Token** | `onIdTokenChanged` で監視し、API呼び出しに使用 |
| **App Check** | reCAPTCHA v3 による不正アクセス防止 |

## 5. ルームシステム

### 5.1 ルーム作成（ホスト）

1. **ルームID** を任意入力（例: `room-abc`, `1234`）
2. **入室パスワード** を任意設定
3. **プレイヤー名** を入力（最大24文字）
4. **フィールド構成** を選択：
   - 🃏 **カードゲームモード** — プレイヤーごとに独立したエリア
   - 🎲 **ボードゲームモード** — 共有プレイエリア＋個別手札
   - 🂠 **トランプモード** — トランプカード画像を自動セットアップ
5. **入室時は全員「観戦者(Spectator)」として入室**（座席は入室後に選択・変更可能）
6. API (`/api/takeover-room`) を呼び出してルーム作成

#### 5.1.1 未ログインユーザーの作成制限
- **作成回数制限**: 未ログイン状態（匿名認証）のユーザーは、**24時間に1回**しかルーム作成（ホスト開催）ができない。
- **判定ロジック**:
  - `localStorage`（キー: `pa:last-guest-room-created-at`）
  - Firestore ユーザープロファイル（`users/{uid}` の `lastRoomCreatedAt`）
  - 上記2箇所の最新タイムスタンプを参照し、作成から24時間未満の場合は作成をブロック。
- **制限時の挙動**:
  - ロビーのルーム作成ボタン下部に「次回作成可能まであと〇時間〇分」と「ログインして作成」リンクを表示。
  - 作成ボタン押下時に「作成制限モーダル」が表示され、次回作成可能時間とともに「ログイン / 新規登録へ」ボタン（`login.html` への導線）を案内。
- **ログイン済みユーザーの作成**:
  - ログイン済み（Google / メール登録）ユーザーは、アクティブなルーム保持上限（無料10部屋 / プレミアム100部屋）の範囲内であれば回数無制限でルーム作成可能。
- **未ログイン作成ルームの有効期限**:
  - 未ログイン状態で作成されたルームは `expiresAt`（作成から24時間後）が設定され、ログイン済みユーザーのルームは永続（または手動保存可能）。
- **作成したルームへの簡単再入室**:
  - 未ログインユーザーがルームを作成後、誤ってロビーへ戻ったりタブを閉じた場合でも、ロビーの「ログインする」ボタンの横に「🚪 作成したルームに入る」ボタンが表示される。
  - ルームが生存中（24時間以内かつ未終了、自身がホスト）の場合のみ動的に表示され、ワンクリックで作成したルームへ再入室（復帰）可能。期限切れや終了時は自動で非表示となる。

#### 5.1.2 ログインユーザーのルーム保持数上限と整理機能
- **ルーム保持数上限**:
  - **無料会員**: 最大 **10部屋**
  - **プレミアム会員**: 最大 **100部屋**
- **判定と制限ルール**:
  - ログインユーザーがルームを新規作成する際、自身がホスト（`hostUid == uid`）かつ未クローズ（`roomClosed !== true`）のアクティブなルーム数を取得・判定。
  - 保持数が上限（無料会員なら10部屋以上）に達している場合、新規作成が一時中断され、不要なルームを削除して「上限未満（無料会員なら9部屋以下）」にするまで作成できない。
- **マイルーム整理モーダル（スロット一覧ウィンドウ）**:
  - 上限超過時にロビー上で「ルーム保持数の上限」モーダルがポップアップ表示。
  - 現在保持しているアクティブなルームの一覧（サムネイル、ルーム名/ID、更新日時、カード枚数/チャット件数、削除ボタン）をカード形式で一覧表示。
  - マイページのマイルーム一覧と同様の感覚で、不要なルームをその場で確認・個別削除（論理削除 `roomClosed: true`）可能。
  - 削除により空きができた（9部屋以下になった）時点で、「作成を続ける」ボタンが有効化（活性化）され、そのまま元のルーム作成（レイアウト選択モーダル等）フローをスムーズに続行できる。
  - モーダル内にはプレミアムプランへの案内（100部屋まで拡大可能）リンクも掲載。

### 5.2 ルーム参加（ゲスト）

1. ルームIDを入力
2. パスワード入力（設定されている場合）
3. プレイヤー名を入力
4. 「開始」で参加（入室時は全員「観戦者(Spectator)」）

### 5.3 ルーム管理

| 項目 | 仕様 |
|---|---|
| **ホスト権限** | ルーム終了、他プレイヤーカード操作トグル、ルーム保存、エリア操作 |
| **手動終了要件** | **ホスト本人**であれば、座席の着席有無に関わらず実行可能 |
| **ハートビート** | 各座席(`heartbeatAt`)、およびホスト(`hostHeartbeatAt`)が**15秒おき**に定期更新 |
| **座席タイムアウト** | `SEAT_STALE_MS = 60秒` — ハートビートが途絶えたら不在と判定され、他者が上書き可能になる |
| **座席の復帰 (Resume)** | リロード等で離脱しても、Firestore上の `claimedByUid` が自分と一致すれば、タイムアウトを待たずに即座に元の席に戻ることが可能 |
| **座席の自動解放** | プレイヤーが新しい席に座った際、以前座っていた席に自分のデータが残っていれば即座にクリアされる |
| **ルーム生存判定** | **いずれかの座席がアクティブ**、または**ホストが観戦者として滞在(更新)**していれば生存 |
| **ルーム自動リセット** | 全関係者の不在が60秒続いた場合、他ユーザーによる「ホスト乗っ取り」およびデータ初期化が可能 |
| **退室** | ゲストは退室ボタン、ホストはルーム終了ボタン |
| **ルーム終了** | クライアント側（または `/api/close-room`）でサブコレクション（cards/chat/seats）一括削除 |
| **パスワード認証** | SHA-256ハッシュで照合 |

### 5.5 座席管理システム（ライフサイクル）

座席（SEAT1〜SEAT8）の状態管理は、Firestoreの `seats` コレクションを通じてリアルタイムに行われる。

1. **着席 (Claim)**:
   - 観戦者が空席（またはタイムアウトした席）を選択すると、Firestore トランザクションによって `claimedByUid` と `displayName` が書き込まれる。
2. **維持 (Heartbeat)**:
   - 着席中のクライアントは、バックグラウンドで15秒ごとに `heartbeatAt` に現在時刻を書き込む。
3. **離脱 (Release)**:
   - 「座席を離れる」ボタンを押すと、`claimedByUid` 等が null クリアされ、即座に空席に戻る。
4. **意図しない切断 (Stale)**:
   - ブラウザが閉じられたり通信が途絶えた場合、60秒（`SEAT_STALE_MS`）経過後に他のプレイヤーから「不在」と判定される。
5. **復帰 (Resume)**:
   - リロード後に再度同じルームに入った際、まだ Firestore 上に自分の UID が残っている席があれば、ボタンが「(あなたの席)」として有効化され、即座に着席状態を復旧できる。
6. **移動に伴う掃除 (Cleanup)**:
   - プレイヤーが別の座席番号を選んで着席に成功した場合、以前座っていた古い座席番号のデータはシステムによって自動的に削除される。

## 6. ゲームフィールド

### 6.1 カードゲームモード

各プレイヤー（SEAT1〜SEAT8）に以下のエリアが独立して配置：

| エリア | 説明 | 可視性 |
|---|---|---|
| **プレイエリア** | カードを出して勝負する領域 | 全員に表示 |
| **デッキエリア** | 山札置き場。整列・シャッフルの中心 | 全員に表示（カードは裏面可） |
| **手札エリア** | 自分だけが表を見られる領域 | 他プレイヤーには裏固定 |
| **捨て札エリア** | 不要カードの置き場 | 全員に表示 |
| **特殊エリア** | 得点・効果・保留など独自用途 | 全員に表示 |

### 6.2 ボードゲームモード

- **共有プレイエリア**（中央の大エリア）
- **各プレイヤーの手札エリア**（SEAT1〜SEAT4 ※デフォルト構成）
- **共有デッキエリア**
- **共有捨て札エリア**

### 6.3 トランプモード
- 既製のトランプカード画像（`dist/TrumpPicture/`）を自動配置
- カードゲームモードのフィールドレイアウトを使用

### 7.6 リアルタイム同期・排他制御とスナップバック・重なり保護
- **操作中ロック**: カードドラッグ開始時に `activeOperator: CURRENT_PLAYER` を付与し、他プレイヤーの同時操作を排他制御。
- **スナップバック保護**: ドラッグ中（`isDragging`）およびドロップ直後（1200ms）は、サーバーからの古いスナップショット座標・zIndexによるDOM上書きをブロック。ドロップ完了後にサーバーの座標・zIndexが追いついた時点で保護を早期解除し、スムーズな操作性を維持。
- **最前面保証（zIndex）**: カード選択（クリック・タップ）時およびドラッグドロップ時に常に最新の最前面 zIndex を再計算・割り当てて Firestore に同期。重ねたカードの後ろに潜り込む現象を防止。

### 7.6 操作権限

カードおよびトークンの操作可否は、「オブジェクトの所有権（オーナー）」と「ホストによる設定」によって制御される。

| 操作者 | ホスト設定：他人の操作 **OFF** | ホスト設定：他人の操作 **ON** |
| :--- | :--- | :--- |
| **オーナー（生成者）** | **すべての操作が可能** | **すべての操作が可能** |
| **他のプレイヤー** | **不可** | **移動・表裏反転のみ可能** |

- **モードによる運用の違い**:
    - **カードゲームモード**: 各自が自分のエリアのカードを扱うため、通常は「他人の操作 **OFF**」で運用する。
    - **ボードゲームモード**: 共通エリアの駒などを全員で順次動かす必要があるため、ホストが「他人の操作 **ON**」に設定して運用することが想定されている。

| 機能 | 説明 |

### 12.1 エリアコンテキストメニュー（ホスト専用）

各エリアをホストが右クリックすると専用メニューが表示される。

| 対象エリア | 表示される項目 |
|---|---|
| **プレイエリア** | 🔍 拡大 / 🔍 縮小 / ➕ エリア追加（デッキエリアを新規追加）|
| **デッキ・手札・捨て札エリア** | 🔍 拡大 / 🔍 縮小 / 🖐 移動 |
| **全エリア共通** | 🖼 エリア画像変更 / 🧹 エリア画像リセット / 🎨 エリア色変更 |

#### エリア画像設定とサイズ選択モーダル
- 右クリックメニュー「🖼 エリア画像変更」からファイルを選択した際の挙動：
  - **カードゲームモード時**: 固定レイアウトのため「画像のサイズに合わせる」は対象外となり、モーダルを表示せず自動的に「現在のエリアサイズに合わせる（全面適合）」として即座に画像が適用・アップロードされる。
  - **ボードゲームモード時**: 設定モーダル（`#area-image-fit-modal`）がポップアップし、以下の2つの適用方法を選択可能：
    - **「現在のエリアサイズに合わせる」**: 現在のエリア寸法を維持し、画像がエリア全面（`background-size: 100% 100%`）に引き伸ばされて表示される（ツール側で無理に縦横比を固定せず、プレイヤーの用意した画像に合わせて隙間なく表示）。
    - **「画像のサイズに合わせる」**: 手札エリアやプレイエリアの幅・高さが、選択した画像の自然解像度（`naturalWidth` × `naturalHeight`）と完全に一致するようにリサイズされる。
- **画像のみをエリア化するスタイリング**:
  - 画像が設定されたエリアには `.has-bg-image` が付与され、元々の青色背景（`#228be6`）や緑色背景（`#2d8`）、点線枠（`border`）、内側余白（`padding`）、および右下のテキストバッジ（`.zone-label`）が非表示・透明化され、画像のみが手札エリア・プレイエリアとして表示される。
  - 「🧹 エリア画像リセット」を行うと、元の背景色・枠線・ラベルが即座に復元される。

#### カードゲームモードのエリア境界線ドラッグリサイズ（ホスト専用・全席同期）
- **操作権限**: ホストのみドラッグリサイズ操作が可能（ゲスト・観戦者には操作ハンドルは非表示）。
- **ドラッグ操作可能な境界（スプリッター）**:
  1. **プレイヤーエリア全体の外枠境界（上下左右ドラッグ・全座席一括連動）**:
     - `.player-area` の外枠四辺（上・下・左・右）をドラッグして、全プレイヤー席の幅（`playerAreaW`）および高さ（`playerAreaH`）を一括拡大／縮小。
     - 外枠ハンドルをダブルクリックすることで、画面幅にフィットするデフォルト自動サイズへ即座にリセット可能。
     - 内部の各エリア（特殊・メイン・デッキ・捨て札・手札）は外枠の伸縮に比例して自然にサイズ連動。
  2. **特殊エリア境界（左右ドラッグ）**: 特殊エリア（左列）の横幅比率（`col1`）を変更。
  3. **手札エリア境界（上下ドラッグ）**: 手札エリア（下段）の高さ比率（`handH`）を変更（全レイアウト対応）。
  4. **サイドエリア境界（左右ドラッグ）**: 捨て札・デッキエリア（右列）の横幅比率（`col3`）を変更。
  5. **捨て札／デッキ境界（上下ドラッグ）**: 捨て札とデッキの上下高さ比率（`discardH`）を変更。
  6. **カスタム1 特殊1／特殊2境界（上下ドラッグ）**: カスタム1レイアウト時の特殊エリア1と特殊エリア2の上下高さ比率（`custom1Special1H`）を独立して変更。
  7. **カスタム2 特殊／デッキ2境界（上下ドラッグ）**: カスタム2レイアウト時の特殊エリアとデッキエリア2の上下高さ比率（`custom2SpecialH`）を手札エリアとは独立して変更。
- **全座席一括同期**:
  - ホストが任意の座席（SEAT）の仕切り線または外枠をドラッグすると、ドラッグ中リアルタイムに全座席（SEAT1〜10）が同一サイズ・同一比率で伸縮連動する。
  - ドロップ（離した時点）で Firestore `rooms/{roomId}` の `cardLayoutRatios` に保存され、部屋にいる全クライアントへ即時リアルタイム同期される。

#### エリア拡大・縮小
- トークンと同様の `scaleLevel` 方式（CSS `transform: scale()` を適用）
- ホストが操作すると Firestore `rooms/{roomId}/areas/{areaId}` に同期
- 全クライアントにリアルタイム反映される

#### エリア移動
- 移動を選択すると、エリアが半透明の状態でマウスカーソルに追従する
- 他のエリアと重ならない場所でクリックすると配置確定
- 重なり検知：`intersects()` 関数で衝突判定。重なっている場合は赤くハイライトして配置不可
- 配置確定後、`isAbsolute: true` と座標・サイズが Firestore に保存される

#### デッキエリア追加
- プレイエリアのメニューから「デッキエリア」を選択すると新しい仮エリアが生成される
- フィールド内の任意の場所にドロップできる
- Firestore に `dynamic-deck-{timestamp}` 形式の一意なIDで保存される

### 12.2 プレイ人数変更（ホスト専用）
- ホスト専用操作パネルの「人数変更」ボタンから 1人〜10人 の範囲で動的に変更可能。
- 変更内容は Firestore `rooms/{roomId}`（`playerCount`）に保存され、全参加クライアントにリアルタイム配信。
- カードフィールド（`.player-1`〜`.player-N`）、手札エリア、座席選択モーダル、HPパネルが即座に連動更新。
- 縮小された座席に着席中だったプレイヤーは自動的に観戦者（Spectator）へ安全に移行。

### 12.3 エリアサイズ調整メモリ＆自動スナップ（ホスト専用）
- **サイズ調整メモリ スイッチ**: ホスト専用操作パネルで ON/OFF 切り替え可能（デフォルト: ON、`localStorage` に保存）。
- **絶対目盛り表示**: エリアのリサイズドラッグ中、`#field` 全体に20pxの細線および100pxの太線による青色の半透明グリッドオーバーレイを表示。
- **自動スナップ**: スイッチがONの場合、四辺の座標および幅・高さが `#field` の絶対座標系（20px刻み）に自動吸着。
- **寸法バッジ**: リサイズ中、マウス付近にリアルタイムで現在の寸法（例: `680 × 480 px`）をバッジ表示。

### 12.4 ホバー時カード拡大＆動的操作権限カーソル
- **ホバー時カード拡大（ホスト専用ON/OFF）**:
  - ホスト専用操作パネルの「ホバー時カード拡大」スイッチで切り替え可能（デフォルト: ON、Firestore `rooms/{roomId}.cardHoverZoom` および `localStorage` に保存）。
  - ONの場合、カードにマウスを乗せると滑らかに拡大（`scale: 1.08`）し、一時的に最前面（`z-index: 25000`）へポップアップして手札や重なったカードの視認性を向上。
  - ボード（`.is-board`）、メモ・ノート（`.memo`, `.note`）、ダイス（`.dice`）、およびドラッグ中のカードは拡大から除外。
- **動的操作権限カーソル（手のひらマーク / 禁止マーク）**:
  - カードにカーソルを乗せた瞬間（`mouseenter` / `mouseover`）に動的に操作権限（`canOperateCard`）を判定。
  - 操作可能なカード（自分のカード、またはホストの「他プレイヤーカード操作ON」時）は手のひらマーク（`cursor: grab` 🖐️）を表示。
  - 操作不可のカード（他人のカード、観戦者時、他人が現在ドラッグ中）は禁止マーク（`cursor: not-allowed` 🚫）を表示。
  - 座席に着席（または離席）した際、および「他プレイヤー操作」設定変更時に盤面上の全カードの `data-owner` とカーソルを一括即時更新。

### 12.5 カード回転設定（ホスト専用）
- **回転方向**: 右回り（時計回り / `cw`、デフォルト）/ 左回り（反時計回り / `ccw`）。
- **1回の回転量**: 90度（デフォルト）、45度、30度、180度 から選択可能。
- **回転反転（往復トグル）**:
  - なし（デフォルト）: 操作ごとに設定方向・角度へ連続回転。
  - あり: 1回目の操作で設定方向・角度へ回転（タップ）、2回目の操作で反対方向に回転して元の角度へ復帰（アンタップ）。以降1回目と2回目を交互に繰り返す。
  - 複数選択カードの一括回転時も全員が足並みを揃えて一括タップ／アンタップ。
  - 「全カード/選択カード向きリセット」時はトグル状態も未回転へ初期化。
- **操作トリガー**: PCはダブルクリック、iPad/スマホはダブルタップ。
- **保存と同期**: Firestore `rooms/{roomId}`（`cardRotateDir`, `cardRotateAngle`, `cardRotateToggle`）および `localStorage` に保存され、ルーム内全プレイヤーにリアルタイム同期。

### 12.6 チャット＆ログ設定（ホスト専用編集、ゲスト閲覧のみ）
- **時間表示形式設定**: `minute` (時分), `second` (時分秒), `millisecond` (時分秒.ミリ秒) をホストが変更可能。
- **イベント別ON/OFFトグル**: 違反プレイ防止やログ量抑制のため、13種類のイベント（画像読み込み、セーブ/ロード、検索、表裏、シャッフル、選択、最背面、まとめ、裏画像、ダイス/コイン、回転、削除、HP/カウンター）を個別にON/OFF可能。
- **ゲスト権限**: ゲストは閲覧専用。設定値は全プレイヤーにFirestoreを通じてリアルタイム同期。
- **かるたモード活用**: 「時分秒.コンマ」表示と「カード選択ログ」を併用することで、ミリ秒精度での先取判定が可能。

## 13. サーバーレスAPI

### `POST /api/close-room`

ホストがルームを完全削除する。

| パラメータ | 型 | 説明 |
|---|---|---|
| `roomId` | string | 対象ルームID |
| `idToken` | string | Firebase Auth IDトークン |

**処理フロー**: トークン検証 → ホスト確認 → roomClosed フラグ → サブコレ削除 → 親doc削除

### `POST /api/takeover-room`

ルームの作成または（全員不在時の）ホスト引き継ぎ。

| パラメータ | 型 | 説明 |
|---|---|---|
| `roomId` | string | 対象ルームID |
| `idToken` | string | Firebase Auth IDトークン |

**処理フロー**: トークン検証 → ルーム存在確認 → 存在しないならルーム新規作成 / 既存なら全席不在（60秒以上経過）チェック → seats(1-8席)/cards 初期化 → hostUid 更新

### `POST /api/create-checkout-session`
Stripe 決済のチェックアウトセッションを作成（プレミアムプラン: 月額500円の定期課金サブスクリプション）。Firebase IDトークンを検証し、決済完了後は `mypage.html?session_id={CHECKOUT_SESSION_ID}` へリダイレクト。

### `POST /api/create-portal-session`
ユーザーの Stripe カスタマーポータルセッションを作成。マイページの「サブスクリプションを管理」から呼び出し、ユーザーが自らプランの解約や支払方法変更を行えるStripeポータルへリダイレクト。

### `POST /api/stripe-webhook`
Stripe からの Webhook を処理し、Firestore（`users/{uid}`）のプレミアム権限を自動更新。
- `checkout.session.completed`: `premium: true`, `stripeCustomerId`, `stripeSubscriptionId` を保存。
- `customer.subscription.deleted`: `premium: false` に更新（解約処理）。
- `customer.subscription.updated`: サブスクリプション状態の変更を同期。

## 20. 既知の課題・改善候補

1. **`game.module.js` が巨大**（5700行超 / 218KB）— モジュール分割の余地がある
2. **`sw.js` が難読化済み**（PropellerAds関連） — 本来のPWAキャッシュ制御が不明瞭

4. **`index.html` の `<style>` 内にChatGPTとの対話テキストが残存**（L195–L203あたり）
5. **i18n が JS 内ハードコード** — 翻訳ファイル分離でメンテナンス性向上の余地
6. **Firebase 設定値** — `mypage.html` にハードコードされている（`game.module.js` はプレースホルダ方式）
7. **エリア移動後のコンテキストメニュー** — 移動されたエリアはFirestore同期後にIDが正しく付与される前提であり、タイミングによってはIDが欠落するケースがあり得る（要継続調査）

  - `scripts/header-auth.js` による Firebase Auth 状態監視および動的パーシャル展開（`MutationObserver`）に対応。

### 21.3 「一般ゲーム」名称変更およびチェス専用正方形レイアウトの実装 (2026-09-24)
- **「公式ゲーム」から「一般ゲーム」への名称変更**:
  - ロビー（`lobby.html`）、モーダル、ゲーム画面（`game.html`）のセットタブ、遊び方ガイド（`howto.html`）での表記を「一般ゲーム」「一般セット」に統一。

  - **不要エリアの排除**: チェス選択時（`fieldMode === 'chess'` または `fieldLayout === 'playonly'`）に中央のデッキエリア（黄）および捨て札エリア（赤）、手札エリア、および「プレイエリア（共有）」ラベルを非表示化。
